# 因子报告（Alphalens 式）设计方案

> 目标：把「429 个 Alpha 因子到底哪个能用」这件事从脚本结论变成**一页可看的标准报告**——
> 分位收益、换手率、相关性去重三件事一屏回答，落在技能中心「因子报告」页签。
>
> 缘起：对照开源框架选型（backtrader/vectorbt/zipline/finrl 那类）时确认的一个真空白 ——
> 我们有 429 个因子、有 IC 检验脚本，但没有 Alphalens 那种**成体系的因子体检产出**。

---

## 一、结论先行

1. **数据全都现成**：因子值在 `data/quantdb/6_ml_datasets/alpha_library/dt=*/data.parquet`
   （429 列 = Alpha158 的 158 + Alpha101 的 101 + GTJA191 的 170，2599 个日分区 ≈ 19 GB），
   前瞻收益在 `alpha_library_labels/`（`fwd_ret_1/2/5/10/20`，尾部未落地的日期自动跳过）。
2. **一次遍历算完三件事**：把每日横截面取秩后，秩矩阵的 `RᵀR` 累加得到 429×429 秩相关矩阵，
   秩分组得到十分位组合收益与换手 —— 一趟扫描同时产出，实测 **1138 个交易日 / 8 进程 / 150 秒**。
3. **快照 + 按需明细两层**：全量排行与相关性走快照 JSON（1.5 MB）；
   单因子明细（分位净值、IC 序列、换手序列）按需扫描分区，首次 ~3s、服务端缓存 10 分钟。
4. **不做的事**：不引入新依赖（numpy 双排序 + pyarrow 列裁剪），不改因子数据，
   不替换既有 IC 脚本（本脚本窗口指标与它同口径，可用于交叉验证）。

## 二、口径（写死在这里，避免各处解释不一致）

| 指标 | 口径 |
|---|---|
| 秩 IC | 每日横截面因子秩 vs 前瞻收益秩的 Pearson（= Spearman），窗口内按日均值 |
| ICIR | IC 均值 / IC 标准差；t 值 = ICIR × √样本数 |
| IC 胜率 | IC > 0 的交易日占比 |
| 分位收益 | 按因子值升序等分 10 组，组内前瞻收益均值；Q1 = 因子值最小 |
| 多空价差 | Q10 − Q1 的平均前瞻收益（每个调仓周期） |
| 单调性 | 分位序号与分位收益的秩相关（±1 = 完美单调） |
| 换手率 | 十分位成员相对前一交易日的变动比例（单边，按当日有效样本归一） |
| 相关性 | 秩相关矩阵，逐日 `RᵀR` 累加后中心化；NaN 秩用该列**中位秩**填充 |
| 净值曲线 | 分位组合按 `前瞻 k 日收益 ÷ k` 折算到日均后复利（重叠期近似，图表内已标注） |

窗口默认**近 5 年**（`--years 5`），可选 `--start/--end/--step`；快照元数据里记录窗口与生成时间，
页面顶部原样展示 —— 避免「看的是哪个区间」说不清。

## 三、组件与落点

```
backend/scripts/build_factor_report.py        快照构建（离线，跑在服务器/容器里）
backend/services/engine/factor_report/
├── service.py                                快照读取 + 单因子按需计算（线程池并行读分区）
└── router.py                                 /api/v1/factor-report/{summary,detail,correlation,related}
backend/services/api/routers/engine_proxy.py  网关转发 factor-report 前缀
electron/src/features/skills-center/
├── components/factor-report/                 因子榜 + 四张图 + 相关性热力图
├── services/factorReportService.ts           API 封装
└── types/factorReport.ts                     类型（与后端字段一一对应）
prompts/factor-report.md                      技能中心提示词模板（QuantBot 侧用法）
```

**数据流**：脚本产出快照 JSON（`6_ml_datasets/alpha_library/report/factor_report.json`，`/data` 卷内，
不进 git）→ 引擎服务读快照返回排行/相关性；明细按需扫分区 → 前端左榜右图。

## 四、维护

- **刷新快照**：`docker exec quantmind python3 backend/scripts/build_factor_report.py`
  （数据更新后跑一次即可；可挂到每日同步之后，暂未自动化）
- **换前瞻期**：`--horizon fwd_ret_10`，页面默认读 T+5（快照的 horizon 字段）
- **快照缺失/过期**：页面顶部显示快照生成时间；缺失时给出「先跑脚本」的明确提示（不静默空页）
- **加因子库**：新库只要进了同一张因子表就自动出现（`library` 由列名前缀推断：
  `a158_*` / `a101_*` / 其余按 `gtja191`）

## 五、已知边界

- 相关性是**窗口内日均**口径（逐日秩相关矩阵的平均），不是「全样本一次秩相关」；
  两者在因子分布随时间的场景下会有差异，页面已标注「近 5 年日均」。
- 换手率是**十分位组合**的成员变动，不是因子值本身的换手；调仓成本建模仍需回测侧配合。
- 明细接口首次 ~3s（扫 250 个分区 ×2 文件），并发高时靠进程内缓存顶；
  若要给多人同时用，建议把最近查看的因子明细也落成快照。
